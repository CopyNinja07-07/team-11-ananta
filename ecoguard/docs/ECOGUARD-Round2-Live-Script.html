Questions the jury may ask

Short answers

Why Figma?
Components, variants, auto-layout, variables and a clickable prototype in one file, shared by one link, free for students.
How did you build the prototype?
Frames for every screen, hotspots on every link (Navigate, Smart animate), an after-click copy of the screen for every button, tab and slider (Dissolve, keeps the scroll), an overlay for the phone menu, an animated GIF for the 3D view, and fixed layers for the sidebar and top bar so long pages scroll.
Is the data real?
Every number comes from our simulated Academic Block A (a year of 15-minute readings with 558 injected faults), and the 659 real buildings page uses the open BDG2 data set. Each screen is labelled simulated or real.
How do design and code stay the same?
The Figma variables are the Tailwind tokens of the React app, and the hi-fi screens are the real app screens. Handoff is the variables plus the repo.
Can it work with real hardware?
Yes. An ESP32 sends the same JSON reading to /api/ingest (or MQTT). The simulator uses exactly that path, so real boards replace it with no other change.
What about empty, error and loading states?
PDF page 17 and every screen: no readings yet, nothing wasted, server offline, power cut, loading. Contrast and 44 px touch targets are on the same page.
Which AI models are inside?
A room model (Huber regression) for expected power, nine checks on top, YOLO for people counts, LightGBM baselines and an LSTM day-ahead forecaster trained on real BDG2 buildings. Numbers are always computed in code; advice is fixed English and Hindi sentences.
